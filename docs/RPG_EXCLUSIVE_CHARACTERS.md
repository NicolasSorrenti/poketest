# RPG account-exclusive characters

The canonical allowlist is `rpg_character_access.js`. Use stable Character Pack IDs as keys and confirmed Supabase Auth emails as allowed values. Example:

```js
const exclusiveEmails = Object.freeze({
  barb: Object.freeze(['nicolassorrenti2@gmail.com'])
});
```

The public RPG entry point `/rpg.html` loads `rpg_character_bootstrap.js` first. That bootstrap calls `GET /api/rpg/character-packs` with the saved Supabase access token (refreshing if necessary), and only then loads the rest of the RPG JavaScript in dependency order. The server looks up the user by validating the token with Supabase Auth. Guests, invalid tokens, and unverified or non-allowlisted accounts receive only the public roster.

`rpg_character_packs.generated.js` is deliberately not served as a public file; it is an internal server-side module generated by `npm run characters:build`. Do not re-add it as a public script: this would expose the full exclusive roster.

## Install Barb

Extract `Barb_Complete_Character_Art_and_Story_2026-10-23.zip` at the **repository root** (including `characters/barb/` and `rpg-assets/characters/barb/`). Then run:

```sh
npm run characters:validate
npm run characters:build
npm run test:rpg
node test_rpg_character_access.js
git add characters/barb rpg-assets/characters/barb rpg_character_packs.generated.js rpg_season_events.js
git commit -m "feat(rpg): install Barb account-exclusive character pack"
git push origin main
```

The owner must sign in to the RPG cloud system using the exact confirmed Supabase account email. Switching accounts reloads the roster automatically. Nonowners cannot encounter, duel, schedule, or progress Barb via the standard RPG frontend.

## Scope

This is **gameplay visibility/access gating**, not secrecy of artwork or invulnerable anti-cheat. RPG gameplay remains client-side and a public source repository or public static images can expose asset files directly. For true confidential assets or anti-cheat enforcement, also restrict static asset delivery and validate all scene/duel/save actions on an authenticated server. The current system is intended for creator testing, not DRM.

## Tests

`node test_rpg_character_access.js` checks allowlisted/unlisted and case-insensitive email behavior. `npm run test:rpg` covers compatibility with the standard Character Pack registry. The server route intentionally returns all ordinary characters to everyone and includes Barb only for the verified owner.
